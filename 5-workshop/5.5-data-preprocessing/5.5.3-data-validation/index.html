Raw Data Validation

Data published from AWS IoT Core through Amazon Kinesis Data Firehose is automatically buffered into batches before being delivered to Amazon S3. This improves throughput and reduces storage costs. However, Firehose output often contains Concatenated JSON, where multiple JSON objects are written together (}{) without line breaks.

In this section, we will create a Python validation script to fix this format and perform basic quality checks on the raw dataset before moving to the preprocessing stage.

1. Prepare the Working Environment (WSL)

Open WSL (Ubuntu) and create a Python virtual environment.

python3 -m venv .venv
source .venv/bin/activate
pip install pandas

2. Create the Validation Script

Create a file named raw_validation.py and paste the following code into it.

The script will:

  • Read raw data from Amazon S3.
  • Convert Concatenated JSON into JSON Lines format.
  • Validate the schema.
  • Validate data types.
  • Detect missing values.
  • Validate UTC timestamps.
  • Validate Device IDs.
  • Check business rules (PM2.5 must not be negative).
  • Detect duplicate records.
import pandas as pd
import json
import io

def validate_data(file_path):
    print("--- RAW DATA VALIDATION REPORT ---")

    try:
        # Read the entire raw file
        with open(file_path, 'r', encoding='utf-8') as f:
            raw_content = f.read()

        # Fix Firehose concatenated JSON
        formatted_content = raw_content.replace('}{', '}\n{')

        # Read as JSON Lines
        df = pd.read_json(io.StringIO(formatted_content), lines=True)

        print("=> Firehose formatting fixed successfully. Starting validation...\n")

    except Exception as e:
        print(f"File read error: {e}")
        return

    # 1. Schema validation
    required_fields = [
        'device_id',
        'timestamp',
        'pm2_5',
        'pm10',
        'temperature',
        'humidity'
    ]

    missing_cols = [
        col for col in required_fields
        if col not in df.columns
    ]

    print(f"[Schema] Missing columns: {missing_cols if missing_cols else 'None'}")

    # 2. Datatype validation
    print("\n[Datatype]")
    print(df.dtypes)

    # 3. Missing values
    print("\n[Missing Values]")
    print(df[required_fields].isnull().sum())

    # 4. Timestamp validation
    try:
        df['timestamp'] = pd.to_datetime(df['timestamp'], utc=True)
        print("\n[Timestamp] UTC format: Passed")
    except Exception as e:
        print(f"\n[Timestamp] Invalid: {e}")

    # 5. Device ID validation
    invalid_stations = df[
        df['device_id'].isnull() |
        (df['device_id'] == '')
    ]

    print(f"\n[Station] Invalid Device IDs: {len(invalid_stations)}")

    # 6. Business Rule
    negative_pm25 = df[df['pm2_5'] < 0]

    print(f"\n[Business Rule] Negative PM2.5 records: {len(negative_pm25)}")

    # 7. Duplicate detection
    duplicates = df[
        df.duplicated(
            subset=['device_id', 'timestamp'],
            keep=False
        )
    ]

    print(f"\n[Duplicate] Duplicate records: {len(duplicates)}")

    # Export sample records
    if len(negative_pm25) > 0:
        negative_pm25.head(5).to_json(
            "sample_invalid_records.json",
            orient="records",
            lines=True
        )

    valid_records = df[df['pm2_5'] >= 0].head(5)

    valid_records.to_json(
        "sample_valid_records.json",
        orient="records",
        lines=True
    )


if __name__ == "__main__":
    validate_data("sample_raw_data.json")

`

3. Download a Sample File from Amazon S3

After Amazon Kinesis Data Firehose delivers data to Amazon S3, navigate to your bucket and open the following directory:

raw/year=2026/month=07/day=26/hour=14/

You should see one or more data files automatically generated by Firehose.

Download one of these files.

Rename the downloaded file to:

sample_raw_data.json

Place it in the same directory as raw_validation.py inside your WSL environment.

4. Run the Validation Script

Open the WSL terminal and navigate to the directory containing the validation script:

cd data

Then execute the script:

python raw_validation.py

If the script runs successfully, a validation report similar to the one below will be displayed.

The report includes:

  • Required schema validation.
  • Data type validation.
  • Missing value detection.
  • UTC timestamp validation.
  • Device ID validation.
  • Business rule validation (PM2.5 must not be negative).
  • Duplicate record detection.

If invalid records are detected, the script will automatically generate sample files containing the problematic records for further inspection.

After completing this step, the raw dataset is ready for 5.3.4 - Data Preprocessing and Standardization.
